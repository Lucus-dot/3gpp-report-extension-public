# 溯源与标注法则

> 本文件管**每一句话的合法性**。续篇的价值不在"写得多"，而在"每句都能指回原文"。

## 一、权威层级的判定顺序（不可跳级）

```
主席报告（Chair notes <meeting>_eom）
  └─ 唯一落槌来源。Agreement / Working assumption 逐字照录，不改写、不合并、不代为实现收敛。
        ↑ 只有在主席报告里出现 "Agreement:" / "Working assumption" 才算落槌
FL Summary #1..#n
  └─ 会中对齐稿。可用来恢复"哪个议题在第几轮被讨论、谁主张什么"，
     其 "Agree / Proposal / ***Proposal" 一律视为未落槌。
        ↑ 常见误用：把 FL 里的 "Agree to support" 写成结论 → 直接作废全文可信度
公司 TDoc
  └─ 只证明"某公司主张过 X"。永远不能证明"会上达成了 X"。
tdoc 列表（主席报告附录）
  └─ 唯一可用于"篇数统计"和"公司花名册"的清单。不要用 FL 编号推断篇数。
```

**开工第一件事**：把主席报告的目标议程项段落逐字导出为 `_eom_<agenda>_verbatim.txt`。
之后所有 `【原文】` 都从该文件复制，不从记忆里写。

## 二、标注四件套

| 标记 | 允许出现的内容 | 禁止出现的内容 |
|---|---|---|
| `【原文】` | 逐字文本，含公式、Note、FFS 清单 | 任何缩写、改写、翻译、合并 |
| `【解读】` | 技术含义、与上次会议的差异、遗留空隙、技术论据 | 新事实（"据说""实际上通过了"） |
| `【折算】` | 由公式算出的数，必须带 formula + assumptions | 手算结果（一律走 `skillctl calc`） |
| `【映射】` | WID 条目 + 预估受影响 TS 功能块 | 精确到条款号（除非已核实） |

**顺序固定**：原文 → 解读 → 映射。读者应能只读 `【原文】` 就完成核实。

## 三、六条铁律

**唯一真源是 `SKILL.md` 的「禁止事项」1–6。本文件不再重复**——曾经两处各写一份，
措辞还不一致（一处漏了"不升格""计数自证"），读者不知道该信哪份。要看规则去 SKILL.md。

## 四、附录 B（勘误登记）的写法

只登记**不影响结论骨架**的修正：数值、编号、术语口径。
若某处修正会推翻原报告的结论骨架，不做附录登记，而是**另写一份新的分析文件**并在两份文件里互相引用——原文件仍然不动。

| 列 | 写什么 |
|---|---|
| 原报告位置 | §x.y + 小节标题 |
| 原表述 | 逐字引用（含错误写法，便于检索） |
| 更正 | 正确表述 + 一句为什么 |
| 依据 | 一手源文件名 + 段落定位 |

> 校验器对"引用错误写法"的行有豁免：只要该行同时含 `更正 / 应为 / 原表述 / 反例 / ✗` 之一，`skillctl check` 只报 WARN 不报 ERROR。
