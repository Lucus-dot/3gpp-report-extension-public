# 数值折算手册

> 一句原则：**会议里每个数字都要能指到"某张表的某一行、哪组参数"；指不到的数字不许写进报告。**

全部计算走工具，不手算：

```bash
python <skill>/scripts/skillctl.py calc all        # 全套（默认按 NTN 场景）
python <skill>/scripts/skillctl.py calc tac --neg 2903.6 --pos 5807.2 --mu 0 1 2 3
python <skill>/scripts/skillctl.py calc wf1 --range-khz 127.08 --k 8 --fc 30
python <skill>/scripts/skillctl.py calc wf2 --range-khz 127.08 --ppm 0.01 --fc-list 30 2
python <skill>/scripts/skillctl.py calc opt3 --fc 30 --ppm 0.01 --k 8
python <skill>/scripts/skillctl.py calc pos
```

## 一、定时类（TAC）

| 量 | 公式 | 备注 |
|---|---|---|
| `Tc` | `1/(480000×4096) s = 0.5086 ns` | TS 38.211 |
| legacy TA 粒度 | `16·64·Tc/2^µ = 1024·Tc/2^µ` | µ=0 → **0.52083 µs**；每升一档 µ 减半 |
| legacy RAR TAC | 12 bit，`T_A ∈ 0…3846` | µ=0 时最大 **+2.003 ms**，且**只能单向推进** |
| 所需位宽 | `bits = ⌈log2(max(正步数, 负步数))⌉ + 1` | `+1` 是符号位 |

**易错点**
- 步数取整用 `ceil`（量程是"至少要覆盖到"），不要 `round`。浮点下 5807.2/0.260417 会落在 22299.6，`ceil` → 22300。
- "量程扩大 N 倍"要跟 **legacy 单向最大值**比，不是跟"某个对称量程"比。
- 位宽之争几乎从来不是算术问题，而是**量程怎么取**（按 GEO 最坏还是按 LEO 典型）——写报告时要把这一点点出来，否则读者会以为有人算错了。

## 二、频率类（FAC）

| 框架 | 粒度定义 | 量程折算 |
|---|---|---|
| WF1（SCS 型） | `gran = SCS / 2^k`（**除以**，不是乘） | `ppm = gran / fc` |
| WF2（ppm 型） | `gran = p(ppm) × fc` | 步数与 SCS 无关 |
| Option 3（折中） | `gran = SCS / 2^k`，k 使 `gran/fc < target` | `k_min = ⌈log2(SCS/(target×fc))⌉` |

**必做的三个对照**
1. **同一框架换 SCS**：WF1 的位宽随 SCS 单调下降（低 SCS 粒度细 → 步数多）。
2. **同一框架换频段**：绝对 Hz 量程按 TR 表缩小时，**ppm 量程未必缩小**（载频降得比 Doppler 更快）。这一条最容易被漏，且能直接解释两派为何各自主张。
3. **候选值 vs 自身约束**：例 `k=[8]` 与 `"<0.01 ppm"` 在 120 kHz/30 GHz 与整个 S 频段不相容。这类"自相矛盾"必须写成硬结论 + 解空间（改 k、按频段分档、或换框架）。

**易错点**
- `SCS/2^k` 在 15 kHz、k=8 时是 **58.59 Hz**，量级正确；写成 `SCS×2^k` 会得到 MHz 量级，物理上不可能——这是最容易犯且最难被读者发现的错。
- 量程与粒度的单位要统一到 Hz 再取整，不要 kHz/Hz 混算。
- WM/WA 给出的"at least for the Ka band"是限定语，不是全频段结论；报告里要写出另一频段的反向结果。

## 三、几何类（参考位置量化）

| 量 | 公式 | 典型值 |
|---|---|---|
| 环回定时误差 | `t_rt = 2Δd/c` | 20 m → **133 ns**；50 m → 334 ns；150 m → **1.0 µs** |
| 折合 TA 步数 | `t_rt / 0.52083 µs` | 20 m → 0.26 步；150 m → **1.92 步** |
| 多普勒灵敏度 | `∂f/∂δ ≈ (fc/c)·(v/d)` | Ka/LEO600 天底 ≈ **1.26 Hz/m**；30° 仰角 ≈ 0.47 Hz/m |
| 频偏误差 | `Δf = 灵敏度 × Δd` | X=150 m → **70–190 Hz**；X=20 m → 9–25 Hz |

**用法**：拿 `Δf` 与闭环粒度（如 15 kHz SCS 下 58.6 Hz）比，得到"位置量化误差是否被闭环兜得住"的判断。**这个比值才是选 X 的真实判据**，比"定时误差小于 CP"这类说辞有力得多。

## 四、从 TR 表取数的正确姿势

1. 先定位**表号 + 参数组合**（轨道 / 频段 / UA 直径 / 仰角），四者缺一不可。
2. 同一物理量在不同 Set / Case 下会有**两个值**（例 2903.8 与 2903.6；128.28 与 127.08）。取更保守（更小）的那个，并注明另一值。
3. 抽取 docx 表格时，`python-docx` 的 `cell.text` 会丢公式（oMath）；表格单元格一般无损，但**跨行合并单元格**会重复出现，需按 `id(tc)` 去重。
4. 若只有纯文本抽取件，数字常被拆成多行（`2903` / `.` / `8`）——不要用文本正则找数，回到 docx 表格取。
